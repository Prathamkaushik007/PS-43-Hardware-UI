# PS-43 Hardware Kiosk - Cloudflare R2 Video Storage System

Production-ready Public Grievance Kiosk built with React, TypeScript, Vite, and Node.js/Express, featuring direct client-to-cloud video uploads using **Cloudflare R2** with an offline-first **IndexedDB** resilience fallback.

---

## Architecture Overview

```
                 KIOSK FRONTEND
               React + TypeScript
                      │
                      │ Citizen records video
                      ▼
               VideoStudio.tsx
                      │
                      │ MediaRecorder produces Blob
                      ▼
                 Video Blob
                 (video/webm)
                      │
                      ▼
               r2Upload.ts
                      │
                      │ 1. POST /api/videos/upload-url
                      ▼
               Node.js Backend
               (Express + AWS SDK)
                      │
                      │ 2. Generate Presigned PUT URL (3600s)
                      ▼
              Cloudflare R2 API
                      │
                      │ 3. Return uploadUrl + object key
                      ▼
               React Frontend
                      │
                      │ 4. Direct PUT streaming (bypasses backend bandwidth)
                      ▼
              CLOUDFLARE R2 BUCKET
              (ps43-videos)
                      │
                      ▼
              videos/YYYY/MM/<uuid>.webm
```

### Storage Strategy & Resilience Fallback
- **Cloud-First**: Video Blobs stream directly from the browser to Cloudflare R2 using pre-authenticated S3-compatible URLs generated by the Node.js backend.
- **Offline Fallback**: If the network drops or the backend/R2 is unreachable, the recording is **never lost**. It is preserved in the kiosk's local browser database (**IndexedDB**) marked as `uploaded: false` with clear on-screen notifications.
- **Security**: Cloudflare R2 master credentials (`R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`) remain strictly on the backend and are **never exposed** to frontend clients.

## Quick Start

### Prerequisites
- Node.js v18+ (tested on Node v22 and v24)
- npm v9+

### 1. Frontend Setup
```bash
# Install frontend dependencies
npm install

# (Optional) Copy environment template
cp .env.example .env

# Start Vite frontend dev server (runs on http://localhost:5173)
npm run dev
```

### 2. Backend Setup
```bash
# Navigate to backend directory
cd backend

# Install backend dependencies
npm install

# Copy environment template to .env
cp .env.example .env
```

Edit `backend/.env` with your Cloudflare R2 credentials (see configuration steps below):
```env
R2_ACCOUNT_ID=your_cloudflare_account_id
R2_ACCESS_KEY_ID=your_r2_access_key_id
R2_SECRET_ACCESS_KEY=your_r2_secret_access_key
R2_BUCKET_NAME=ps43-videos
PORT=5000
FRONTEND_URL=http://localhost:5173
```

```bash
# Start backend dev server (runs on http://localhost:5000)
npm run dev
```

### 3. Run Both Concurrently (Optional)
From the root workspace directory, you can also run:
```bash
npm run dev:all
```

## Cloudflare R2 Setup Guide

Follow these steps in your Cloudflare dashboard:

### 1. Enable Cloudflare R2
1. Log in to the [Cloudflare Dashboard](https://dash.cloudflare.com/).
2. In the left sidebar, click **R2**.
3. Enable R2 for your account if prompted.

### 2. Create the Video Storage Bucket
1. Click **Create bucket**.
2. Set Bucket Name to:
   ```text
   ps43-videos
   ```
3. Choose location **Automatic** (or preferred region) and click **Create Bucket**.

### 3. Generate API Credentials
1. In the R2 Overview page, click **Manage R2 API Tokens** in the right sidebar.
2. Click **Create API token**.
3. Set Token Name: `ps43-kiosk-token`.
4. Permissions: Select **Object Read & Write**.
5. Specify bucket: Apply to specific bucket `ps43-videos` (recommended principle of least privilege).
6. TTL: Choose your preferred expiration or leave indefinite for long-running kiosk servers.
7. Click **Create API Token**.
8. **Immediately copy**:
   - **Account ID** (found at top of R2 page or in token details)
   - **Access Key ID**
   - **Secret Access Key**
9. Paste these values into `backend/.env`:
   ```env
   R2_ACCOUNT_ID=...
   R2_ACCESS_KEY_ID=...
   R2_SECRET_ACCESS_KEY=...
   R2_BUCKET_NAME=ps43-videos
   PORT=5000
   FRONTEND_URL=http://localhost:5173
   ```

### 4. Configure CORS on Cloudflare R2 Bucket
Because the browser performs a direct `PUT` request to Cloudflare R2, you must enable CORS on the bucket:
1. Open your `ps43-videos` bucket in the Cloudflare Dashboard.
2. Go to the **Settings** tab.
3. Scroll down to **CORS Policy** and click **Add CORS policy** (or Edit CORS policy).
4. Paste the following JSON policy:
```json
[
  {
    "AllowedOrigins": [
      "http://localhost:5173",
      "http://127.0.0.1:5173"
    ],
    "AllowedMethods": [
      "GET",
      "PUT",
      "HEAD"
    ],
    "AllowedHeaders": [
      "Content-Type"
    ],
    "ExposeHeaders": [
      "ETag"
    ],
    "MaxAgeSeconds": 3600
  }
]
```
5. Click **Save**.

## Testing & Verification

### Test 1: Health & Presigned URL Endpoint
Verify the backend is operational:
```bash
# Check service health
curl http://localhost:5000/api/videos/health

# Request a presigned upload URL
curl -X POST http://localhost:5000/api/videos/upload-url \
  -H "Content-Type: application/json" \
  -d "{\"fileName\":\"test.webm\",\"contentType\":\"video/webm\"}"
```
Expected response:
```json
{
  "success": true,
  "uploadUrl": "https://<account_id>.r2.cloudflarestorage.com/ps43-videos/videos/2026/09/...webm?X-Amz-...",
  "key": "videos/2026/09/<unique-uuid>.webm"
}
```

### Test 2: Full Recording & Upload in Kiosk UI
1. Start frontend and backend.
2. Open `http://localhost:5173` in Chrome or Edge.
3. Click **VIDEO** (or press key `V` / `1`).
4. Allow camera permissions, speak your complaint, and click **Stop Recording** (or key `S`).
5. Review the recording preview and click **Submit Grievance Now**.
6. Observe the **AI Processing Modal**:
   - Status badge displays: `Uploading video to Cloudflare R2...`
   - Turns green: `Cloudflare R2: Video upload successful`
7. On the **Receipt Modal**:
   - Verified cloud reference is displayed: `☁️ Cloudflare R2: Cloud Video Synced (videos/2026/09/...)`
8. In the **Local DB Records Modal** (click Database icon or press key `R`):
   - Record displays the `☁️ R2 Synced` pill with the unique object key.
9. Log in to the Cloudflare R2 Dashboard -> bucket `ps43-videos`:
   - Verify the `.webm` file appears in `videos/YYYY/MM/`.

### Test 3: Offline Resilience & Failure Handling
1. Stop the backend server (`Ctrl+C` in backend terminal).
2. Record a video in the kiosk UI and submit.
3. The UI will show: `Saved locally — cloud upload failed`.
4. The ticket is registered without crashing; the video Blob is preserved safely in IndexedDB.
5. In the Records modal, the ticket displays `💾 Local Only`.
